# 王者营地「未授权游戏信息」完全解析

> 搜到这个词的人，基本都在同一个地方卡住：战报里明明有 10 个人，其中一行的昵称却是「未授权游戏信息」，`player_id` 和 `account_id` 全空。
> 这篇把它从接口层面拆开讲清楚。

---

## 一、这行是什么

在营地（`the camp gateway`）的对局详情接口返回里，一个玩家是一段 JSON。正常情况下长这样：

```json
{
  "roleName": "小红",
  "player_id": "1234567890",
  "account_id": "9876543210",
  "heroName": "亚瑟",
  "gradeGame": "12.3"
}
```

授权没了之后，同一行变成这样：

```json
{
  "roleName": "未授权游戏信息",
  "player_id": "",
  "account_id": "",
  "heroName": "亚瑟",
  "gradeGame": "12.3"
}
```

⚠ 三个字段被清空：`roleName`、`player_id`、`account_id`。

---

## 二、为什么会被脱敏

王者荣耀的账号体系里，营地是一个「额外的数据出口」。用户可以选择把游戏里的战绩同步到营地 —— 这个授权默认是关的，或者曾经开过后又关掉/从未开启过。

一旦没有这个授权：
- 营地的**列表接口**（历史战绩）直接返回空
- 营地的**详情接口**（单局 10 人）**仍然返回这一行**，因为这一局已经发生了，别人也看到了他
- 但会把他「能识别身份」的字段清空

⚠ 注意这里的设计逻辑：**脱敏的是身份，不是对局**。服务器没有不给你数据，它只是不告诉你是谁。

## 三、判断方法（代码级）

```python
def is_anonymized(player: dict) -> bool:
    """⚠ 判据只认 roleName，别用 player_id == ''。
    实测有脱敏但 player_id 仍残留的行；也有未脱敏但 player_id 为空的边界号。"""
    return player.get("roleName") == "未授权游戏信息"
```

⚠ 常见错误写法：

```python
# ❌ 错：player_id 为空不代表脱敏
if not player.get("player_id"):
    ...
```

为什么错：有些正常账号的 `player_id` 字段在某些接口版本里就是空的，但 `roleName` 是真实昵称。**只看 roleName**。

## 四、常规思路为什么走不通

社区里流传过几种识别方案，都试过，都卡住了 —— 把结论写在这儿，省得你重复踩：

### ❌ 思路 A：拿昵称模糊匹配

想着「昵称虽然被打码了，但可能残留首尾字符」。

**不行。** `roleName` 是被整体替换成固定字符串 `未授权游戏信息` 的，原始昵称一个字节都不剩。不存在「部分打码」这回事。

### ❌ 思路 B：用段位 / 战力反推

段位、巅峰积分、英雄战力这些字段看起来还在，想着能拿来做唯一标识。

**不行。** 实测这些字段在脱敏行里同样是空的或占位值。而且段位是全服几十万人的公共值，撞车率高到没法用。

### ❌ 思路 C：时间戳对齐

同一局开始时间是一致的，可以按「同一时刻在线」反推。

**不行。** 一局里有 10 个人同时在线，时间戳对所有人相同，它只能确定「这一局」，确定不了「这一行是谁」。

### ❌ 思路 D：去查对方的关注/粉丝关系

**不行。** 营地的社交关系接口对未授权账号一律返回空，而且需要对方授权才能读。

### ⚠ 思路 E：靠区服组合

（大区 + 平台）组合理论上能缩小范围。

**作用有限。** 安卓微信一区这种大区有几十万人，缩完还是几十万。只能当辅助线索，不能单独定位。

## 五、我们实际怎么做的

不在这里展开 —— 这套东西调到能用花了很久，核心是**几层判断叠加**后取交集，任何单独一层都不够。

对外只保证结果，不公开实现。能说的就三条：

1. **识别结果分两级**：`hard`（确定）和 `suspected`（推出来的，标 `☆`）
2. **认不出来就明说认不出**，不硬猜
3. **不保证每一行都能认出来** —— 有的号确实认不出

## 六、置信度必须分级

| 依据 | 置信度 | 标记 |
|---|---|---|
| `player_id` 非空 | 硬证据 | 无标记 |
| `account_id` 非空 | 硬证据 | 无标记 |
| 其他方式推出来的 | **软证据** | `☆ 疑似` |
| 都不成立 | —— | `? 认不出` |

⚠ **不要把所有脱敏行都强行认成某个名字**。宁可留「认不出」，也不要猜错 —— 猜错比查不到严重得多。

## 七、常见误区

### ❌ 误区 1：脱敏号的历史战绩能查

不能。这块拿不到，和用什么工具无关。**只能查已经发生过的单局。**

### ❌ 误区 2：好友标记可以当固排用

战报里有个「双方互加游戏好友」的标记，很多人拿它判断固排。

**不行。** 它统计的是**互加好友**，不是**经常一起玩**。固定搭档往往是没加好友的（代练、路人熟脸），拿它判断会漏掉大部分真固排。

### ❌ 误区 3：布尔字段直接判断就对了

战报里有一批字段是**字符串** `'0'` / `'1'`，不是布尔。

```python
# ❌ 错：'0' 是 truthy，条件永远成立
if player.get("some_flag"):
    ...

# ✅ 对
if str(player.get("some_flag")) == "1":
    ...
```

⚠ 这个坑很隐蔽：代码不报错，结果看起来也正常，只是**所有人都满足条件**了。

### ❌ 误区 4：脱敏号可以靠「换个号再看」绕过

跟你的账号无关。服务端按**对方的授权状态**决定返回什么，你换一百个号，返回的还是「未授权游戏信息」。

## 八、FAQ

**Q：那到底能不能查出来？**
A：能，但不是百分之百。认不出来的会明确标「认不出」，不会硬编一个名字。

**Q：如果我关掉营地授权，别人还能看到我的对局吗？**
A：能看到「你这一局存在」，看不到「这一局是你」。

**Q：为什么我自己的号显示正常，别人的号是未授权？**
A：因为授权是**每个人自己**的开关，不是全局设置。

**Q：这个技术合法吗？**
A：只读取公开战报（和游戏内「对战记录」页看到的是同一批数据），不登录任何账号、不破解、不修改。
