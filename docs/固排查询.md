# 固排查询：谁总跟他一起玩

> 单局只能看到「这一局谁跟他一队」。要回答「他最近一直跟谁双排」，必须跨几十局聚合。

---

## 一、三个概念别混

| 概念 | 定义 | 数据来源 | 单局可见 |
|---|---|---|---|
| **同队** | 这一局和他在同一阵营 | 阵营划分（`acntcampBlue` / `acntcampRed`） | ✅ |
| **好友** | 双方**互相加过**游戏好友 | 战报里的好友标记 | ✅ 但覆盖很少 |
| **固排** | 反复和他在同一队 | **跨局聚合统计** | ❌ 必须多局 |

⚠ 这三者是独立的。一个人可以是固排但没加好友，也可以是好友但只同队过一次。

---

## 二、聚合算法

对每个出现过的人（以能确认的身份作为键）统计：

```
出现局数 = 他出现在目标对局里的总次数
队友局   = 其中和他在同一阵营的次数
对手局   = 其中在对面阵营的次数
胜率     = 队友局中赢的 / 队友局
首见     = 第一次出现的日期
最近     = 最后一次出现的日期
常用英雄 = 出现次数最多的前 3 个英雄
```

### 身份键的优先级

```
1. player_id          硬证据，最可靠
2. account_id          硬证据
3. 其他识别方式     软证据，需标 ☆
4. anon:<局号>:<行号>       完全认不出，只在本局内有效
```

⚠ 第 3 类不公开细节：能认出人的那几层判断，多说一句就是在给人抄。
外围只知道「软证据一律标 ☆」这一条对外承诺。

⚠ **匿名键必须是「全局行号」**。如果用「阵营内下标」（0~4），蓝方第 5 行和红方第 5 行会撞成同一个人。

---

## 三、判断「是真固排」还是「刚好撞上」

⚠ 这是最容易出结论也最容易错的地方。给几条经验线：

| 信号 | 判定 |
|---|---|
| 同队 ≥ 5 局，且跨 ≥ 3 天 | 基本可以认定固排 |
| 同队 ≥ 3 局，且都发生在同一天 | ⚠ 可能只是连打，不算固排 |
| 同队 2 局 | 证据不足，别下结论 |
| 同队 1 局 | 巧合 |

⚠ 还应该看**占比**：如果目标总共打了 10 局，这人出现 8 局 → 强信号；目标打了 200 局，这人出现 8 局 → 弱信号。

### 建议的展示方式

不要只给一个「固排：是/否」，要给**原始数字**：

```
小明   同队 29 局 / 对手 6 局   共 35 局   最近 10-19
```

让客户自己判断。给结论容易翻车，给数据不会。

## 四、未授权号的固排怎么算

对方没授权时，那一行是匿名的。这时候：

1. 先把他认出来（见 [未授权游戏信息](未授权游戏信息.md)）
2. 认出来之后，他就成了一个「有身份键的人」
3. 后面按正常聚合算法统计

⚠ 但要注意：**软证据可能认错**。所以未授权号统计出来的固排，置信度天然比授权号低一档，展示时要标 ☆。

## 六、要不要暴露「首见 / 最近」

⚠ 建议**要**。这两个字段信息量极大：

- `首见 2026-10-02 / 最近 2026-10-18` → 半个月内反复出现，强固排
- `首见 2025-01-03 / 最近 2026-10-18` → 跨了一年多，可能是老朋友
- `首见 == 最近` → 只出现一次，不算固排

而且它们是**绝对日期**，不是「3 天前」这种相对时间。相对时间会抹掉「老号 / 批量开号」这类关键特征。
